# Design outline — откуда выгрузка берёт габарит платы

## Как неправильно

* Нарисовать контур линиями (`axlDBCreateLine`) на
  `board geometry/outline` и считать плату «с контуром»: атрибут
  `d->designOutline` остаётся nil, выгрузка не отдаёт габарит
  (`outline` = nil), рендер по выгрузке масштабируется по extents
  донора (метры вокруг маленькой платы), проверки «пин за контуром»
  молча пропускаются.
* Проверять результат создания по порту/сообщению сценария:
  чтение `d->designOutline` сразу после `axlDBCreateShape` может
  вернуть nil, а в сохранённом файле контур есть. Успех — по дампу
  сохранённого файла.

## Как правильно

* Габарит — shape на **`BOARD GEOMETRY/DESIGN_OUTLINE`** (док AXL,
  02dbdesc: «designOutline — shape/rect на BOARD
  GEOMETRY/DESIGN_OUTLINE, nil если нет»). Это отдельный слой, не
  OUTLINE.
* Создать замкнутым путём (функция требует замкнутость — старт =
  конец):

```skill
p = axlPathStart(list(0:0))
p = axlPathLine(p 0.0 0:70.0)   ; размеры — в единицах платы
p = axlPathLine(p 0.0 120.0:70.0)
p = axlPathLine(p 0.0 120.0:0)
p = axlPathLine(p 0.0 0:0)
r = axlDBCreateShape(p nil "board geometry/design_outline" nil nil)
```

* Линии на `BOARD GEOMETRY/OUTLINE` (производственный контур)
  рисовать параллельно — они нужны для gerber.
* Проверка: выгрузить сохранённый файл и убедиться, что габарит
  прочитался (в наборе — `Board.outline_bbox()`).
* Бонус: когда габарит известен, появляются проверки «пины за
  контуром» — они ловили реальный брак (пин за краем платы).

## Чем подтверждено

Сборка платы из нетлиста скриптом: контур линиями — designOutline
nil; тот же код со shape — designOutline с bBox по контуру; выгрузка
начала отдавать габарит, рендер стал читаемым, появилась проверка
«пин за контуром», нашедшая пин за краем платы.
