# Allegro-Skill

Инструмент для работы с печатными платами Cadence Allegro и схемами
OrCAD Capture скриптами: библиотека на Python, база проверенного знания и
правила её ведения. Клон репозитория и есть папка скилла: Claude Code
видит его как `/allegro`, Kimi Code — как `/skill:allegro`.

Общие правила ведения, проверки и хук — соседний скилл
[Skill-Skill](https://github.com/RungeKut/Skill-Skill); соседний набор для
SolidWorks — [SolidWorks-Skill](https://github.com/RungeKut/SolidWorks-Skill).

```
allegro/                  клон Allegro-Skill в папке скиллов агента
├── SKILL.md              точка входа для ИИ
├── alkit/                библиотека Python
│   ├── skill/alkit.il    SKILL-часть: выгрузка, правка, задание
│   └── tcl/dsn_dump.tcl  выгрузка схемы Capture
├── knowledge/            база знаний
│   ├── 00_ПРАВИЛА.md     правила ведения базы
│   ├── INDEX.md          карта базы и поиск по симптому
│   ├── 10_API/  20_ПРИЁМЫ/  30_ГРАБЛИ/  40_СРЕДА/
├── templates/new_project/ скелет проекта
├── tests/                сквозные проверки на демо-платах Cadence
├── tools/check_docs.py   проверка (обёртка общей из skill-skill)
├── tools/kit_local.py    особое набора для проверки
└── CHANGELOG.md
```

## Что умеет

| Задача | Как | Нужен ли открытый Allegro |
|---|---|---|
| Выгрузить плату: компоненты, выводы, цепи, проводники, переходные, полигоны, DRC | `ak.dump(brd)` | нет — Allegro без окна над копией |
| Картинка платы сверху и снизу — проверка глазами | `ak.png(board, png, side=…)` | нет |
| Расставить компоненты: перенос, поворот, сторона; текст | `ak.place(...)`, `ak.edit(...)` | нет; результат — новым файлом |
| Любой код SKILL над платой | `ak.run(brd, code)` | нет |
| Работа с платой, открытой человеком | `ak.Live()` → `.dump()`, `.run(code, edit=True)` | да |
| Сводка, DRC, неразведённые связи, неразмещённые компоненты, любые отчёты | `ak.summary`, `ak.drc`, `ak.unconnected`, `ak.unplaced`, `ak.report` | нет |
| Gerber, IPC-2581, STEP, PDF с проверкой содержимого | `ak.gerber`, `ak.ipc2581`, `ak.step`, `ak.pdf` | нет |
| Прочитать схему `.dsn` | `ak.read_dsn(dsn)` | Capture не нужен |
| Сверить схему с платой | `ak.compare(sch, board)` | нет |

## Установка на новой машине

```bash
git clone https://github.com/RungeKut/Allegro-Skill.git "<папка скиллов агента>/allegro"
python -m pip install --user Pillow
```

Имя папки — `allegro` (как `name` в `SKILL.md`); рядом нужен скилл
skill-skill. Настройка клона (хук, автор, стоп-лист) — skill-skill,
`knowledge/40_СРЕДА/40-01`; зависимости и проверка окружения —
`knowledge/40_СРЕДА/40-01` здесь. Несколько агентов — по клону в папку
скиллов каждого. Обновление — `git pull`; Claude Code подхватывает его
без перезапуска, другие агенты — не проверено.

Нужны: Cadence SPB с Allegro PCB Editor (проверено на 17.2-2016 S066) и
лицензия уровня, в котором есть SKILL; Python 3.11+ 64-bit; Pillow.

## Быстрый старт

```python
import sys
sys.path.insert(0, r"<папка скиллов агента>llegro")   # корень набора
import alkit as ak

ak.utf8_console()
b = ak.dump(r"D:\проект\плата.brd")            # оригинал не трогается
print(b)
ak.png(b, r"D:\проект\вывод\верх.png", side="top")

s = ak.read_dsn(r"D:\проект\схема.DSN")
ak.compare(s, b)                               # схема -> плата

ak.place(r"D:\проект\плата.brd", {"C11": (10.0, 20.0, 90, "top")},
         save_to=r"D:\проект\плата_v2.brd")
```

Новый проект: скопировать `templates/new_project`, вписать в `KIT`
(`build.py`) корень набора, заменить данные в `params.py`, запустить
`build.py`.

## Как обратиться к набору

```
/allegro сверь схему с платой в D:\Проекты\Плата и нарисуй обе стороны
```

В Kimi Code то же самое — `/skill:allegro ...`. Без команды набор
подключается сам, когда в запросе есть Allegro, Cadence,
OrCAD, Capture, `.brd`, `.dsn`, плата, схема, DRC, Gerber, STEP,
IPC-2581, SKILL — или ошибки вида «No licenses available», «Failed to
open design since it is locked».

### Что стоит указать в запросе

| Пункт | Зачем |
|---|---|
| Путь к плате и схеме | набор работает с копиями, но читать должен оригинал |
| Куда класть результат | правка всегда уходит в новый файл |
| Единицы в заданных координатах | плата бывает в милах; набор единицы не переводит |
| Что считать готовым | картинки, сверка, отчёты, какие выходные файлы |

### Обновить сам набор

```
Занеси в базу знаний: axlDBCreateText на слое ... возвращает nil, если ...
— проверил на копии платы.
```

«Занеси в базу знаний», «запиши в грабли», «добавь в alkit» ведут в
`knowledge/00_ПРАВИЛА.md`: шапка со статусом, строка в `INDEX.md`, строка
в `CHANGELOG.md`, коммит и push.

## Как это устроено

Три пути к Allegro, и у каждого свои правила — они и составляют базу:

* **Пакетный** — `allegro.exe -nographic -product … -p … -s job.scr in.brd`.
  Плата копируется в папку без пробелов и кириллицы (иначе Allegro падает
  или молча открывает пустую плату), сценарий кончается `exit` +
  `fillin no`, итог задания пишет сам код SKILL в файл: ни ошибка SKILL,
  ни код возврата о результате не говорят.
* **Живой** — `WM_COPYDATA` в окно открытого Allegro, как в примере
  Cadence `allegro_sendcmd.c`. Строка длиннее ~250 байт теряется молча,
  модальный диалог блокирует канал, ответа нет — поэтому шлётся только
  `skill load("…/job.il")`, а результат приходит файлами. Правка — в
  транзакции с откатом при ошибке.
* **Утилиты** — `report`, `artwork`, `ipc2581_out`, `step_out`, `pdf_out`
  и `tclsh` с `orDb_Dll_Tcl64.dll` для схем. Их коды возврата тоже врут:
  пустой IPC-2581 с кодом 0, STEP без контура платы с кодом 0.

## Почему скилл, а не MCP-сервер

Главное требование — обновлять набор **во время работы**. Скилл и
библиотека — обычные файлы: правка действует со следующего чтения. MCP
поднимается при старте сессии, и его изменение требует перезапуска
агента (Claude Code, Kimi Code). Подробный разбор — в README соседнего
набора для SolidWorks.

## Что проверено, а что нет

Проверено 24.09.2026 на Cadence SPB 17.2-2016 S066, Windows 10, Python
3.13: всё, что в таблице «Что умеет»; `tests/test_board.py`,
`test_edit.py`, `test_capture.py`, `test_export.py` проходят целиком,
`test_live.py` (ручной, с открытым Allegro) — тоже.

**Не проверено:** другие версии Cadence (17.4, 22.x, 23.x); уровни
лицензий, кроме `Allegro_performance` и `Allegro_Venture_PCB_Designer`;
сверловка (NC drill) без GUI; пересчёт DRC без GUI; цепи выводов в
иерархической схеме (сверка связности для неё пропускается и так и
печатается); правка схемы Capture.

Записи базы помечены статусом; записи без `verified` силы не имеют.

## Проверка после обновления Cadence

```
python tests\test_board.py      выгрузка, отчёты, два источника чисел, картинки
python tests\test_edit.py       перенос, поворот, сторона, текст, откат
python tests\test_capture.py    схема: вхождения, секции, сверка
python tests\test_export.py     Gerber, IPC-2581, STEP, PDF
python tools\check_docs.py      целостность базы знаний
```

Проверки идут на демонстрационной паре из поставки Cadence
(`share/orcad/examples/pcbdesign/pcbdemo1`), файлы поставки не
изменяются. Упала проверка — поведение изменилось: найти запись в базе,
перепроверить, обновить по разделу 7 `knowledge/00_ПРАВИЛА.md`.

## Работа с нескольких машин

В начале — `git pull --rebase`; после каждой правки набора — `git diff`,
`python tools/check_docs.py --project "<папка проекта>"`, коммит, `git
push` сразу. Без права записи правка уходит pull request'ом из своего
форка; сливает только владелец. **В набор не попадает ничего о
проектируемом изделии** — ни в файлы, ни в текст коммита; приметы изделия
— в локальный стоп-лист. Общие правила — skill-skill, 40-02; особенности
набора — `knowledge/40_СРЕДА/40-02`.
